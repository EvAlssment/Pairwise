# Local coding-agent bridge

PairDesk can expose read-only context from the active call to an MCP client running on the same Mac. During any audio or screen call, open **Transcript and local agent access** from the menu-bar call controls, then choose **Enable local agent access** with at least one capability selected.

The prototype supports participant names, transcript text, and one-time window screenshots as separate grants. It creates a Unix-domain socket in the current user's Application Support directory, a call-scoped random credential, and a content-free JSONL audit log at `~/Library/Application Support/PairDesk/agent-audit.jsonl`. The socket and audit file are owner-only. Access ends when the person revokes it or the call ends; re-enabling creates a new credential. The log records grant, denial, read, and revoke events without names, transcript text, or image content. The bridge has no TCP listener, cloud endpoint, persistence of transcript text or screenshots, microphone/audio access, screen stream, or remote-control operation. The MCP helper uses stdio and forwards only individually granted operations to the local socket.

In a call, select any of **Participant names**, **Transcript text**, and **One-time window screenshots**, then enable access. Use **Copy MCP configuration** and add that JSON to the configured MCP client's server list. The copied credential applies only to the current call; after the call ends, enable access again and replace the token in that client's configuration. Revoking access invalidates the copied credential immediately.

MCP tools are `pairdesk_call_participants`, `pairdesk_call_transcript`, and `pairdesk_call_screenshot`. They accept no arguments. The screenshot tool opens Apple's native macOS window picker for every request; the person must choose a window, and only that still image is returned to the local MCP client as PNG (maximum 1920 pixels on the long edge and 2 MB). Cancelling or revoking access shares no image. The helper lists only the tools granted for the current call; without a valid current-call credential, its tool list is empty. The helper is bundled at `PairDesk.app/Contents/MacOS/pairdesk-agent-mcp`. It supports MCP stdio using protocol revisions `2026-07-28` and the legacy `2025-11-25` initialize handshake. It never opens a network port.

The local socket accepts one newline-delimited JSON object per connection: `{"token":"<current-call-token>","method":"capabilities|participants|transcript|screenshot"}`. A successful response has `ok: true` and a `result`; capability-filtered methods return `participants: [{"name":"…"}]`, `segments: [{"speaker":"…","text":"…","time":"…"}]`, or a base64-encoded PNG for the one-time screenshot. Failures return `ok: false` and a fixed error string. Transcript responses are bounded to the latest 40 segments and 600 characters per segment. Socket messages are bounded to 4 MB.

Granting context to a local agent can cause that agent to send the granted names or transcript to its configured model provider, save it in its own history, or otherwise process it. PairDesk cannot control those downstream actions. Share only what is appropriate for that agent and revoke access when it is no longer needed.

## Threat model

The bridge is designed to prevent access from a different local OS account and from clients without the current call's random credential. The socket directory is mode `0700`, the socket and audit file are mode `0600`, credentials are replaced on each grant and invalidated on revoke/call end, and no TCP listener exists. Screenshot access adds a fresh macOS window-picker decision for each request. The audit records access decisions without call content.

This does not isolate PairDesk from other processes running as the same macOS user. The person copies a temporary credential into the MCP client's configuration; another same-user process able to read that configuration or the process environment can reuse the credential while the grant is active. The mode bits do not defend against the same UID. Use only a trusted MCP client, limit the selected capabilities, and revoke the grant after use. The configured agent may also send granted content to its model provider or retain it in its own history.

The bridge has not been validated against every MCP client or under a notarized release. The native screenshot picker and a real MCP client's image rendering still need end-to-end validation on a Mac. Treat those as outstanding release checks; the unit test with a protocol fixture does not prove either UI path.
