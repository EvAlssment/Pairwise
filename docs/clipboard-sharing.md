# Clipboard sharing

Pairwise can move plain text between Macs in the same call. The shared-screen toolbar's **Copy & paste** button makes the main action direct: copy on one Mac with `⌘C`, then paste on another with `⌘V`.

- **Screen sharing enables copy and paste automatically.** No extra clipboard toggle, review offer, or paste approval is required on either Mac. It stops when the screen share ends.
- **Sync clipboard text for this call** is an optional call-wide mode for calls without a shared screen; it is independent of automatic screen clipboard access.
- **Send copied text to one teammate** is the one-off alternative. The receiver reviews it, chooses **Copy to clipboard**, then presses `⌘V` in the destination app. This one-off action does not inject a paste keystroke into another app.

Images and files are not transferred. Text is limited to 64 KiB per clip. LiveKit delivers reliable data in packets of at most 15 KiB, so a clip is sent as up to 33 parts (at most 6 KiB of UTF-8 text and 12 KiB after JSON escaping each) that share an id, and the receiver reassembles them in memory; incomplete clips are dropped after two minutes. Parts go only to current call participants over the call's reliable data channel and are accepted only by their intended recipient. Sync reads the system text clipboard while a screen is shared or the optional call-wide toggle is on; it does not run in the background or outside a call. Ending the share stops automatic screen clipboard exchange. Turning the call-wide toggle off does not disable copy/paste during a screen share. Outside a screen share, a receiver without call-wide sync still gets a reviewable one-off offer.

Background sync never shares pasteboard items that their app marked private: `org.nspasteboard.ConcealedType` (password managers such as 1Password and Bitwarden), `org.nspasteboard.TransientType` (clipboard tools restoring content) and `org.nspasteboard.AutoGeneratedType` (scripted writes). Those copies are skipped by background sync. An explicit shared-screen ⌘C or ⌘V follows the user's action, including marked plain text, without another approval. While sync is on, the in-call panel shows the latest clipboard outcome and the Clipboard button is highlighted. During screen sharing the popover explains that copy/paste is automatic and does not show an approval button.

During automatic screen sharing, the sharer sends eligible copies to viewers; a viewer sends eligible copies to the sharer. Explicit call-wide sync retains its all-participant behavior. Apps that do not mark sensitive copies cannot be filtered.

## Copy and paste while controlling a shared screen

Both Macs must run a version with automatic screen clipboard support. Starting or viewing the share enables clipboard access without a second opt-in. The sharer must share a display or region and allow remote control through macOS Accessibility. Window shares remain view-only.

- **Your Mac → the shared Mac:** copy plain text locally, click the destination in the shared display, then press `⌘V`. Pairwise captures your clipboard when you press Paste, sends it reliably to the sharer, and posts a balanced native Command-V shortcut only after the complete text arrives. The host acknowledges dispatch automatically; delivery or native-input failures are reported to the viewer without an approval dialog. This also works when the interaction first needs a control grant.
- **The shared Mac → your Mac:** select text in the shared display and press `⌘C`. Pairwise asks the remote app to copy, waits for a new clipboard write, then returns that text to your clipboard. Paste into your local app with `⌘V`. If the remote app does not copy text, the operation times out instead of returning an unrelated old clipboard value.

The canvas must have keyboard focus. Shortcuts in other local controls retain their usual behavior. These operations use the screen share's existing authorization and a live control lease; there is no clipboard-specific approval. A paused/revoked lease, source change or disconnect cancels pending work. Missing parts never trigger a paste, and replayed clips do not paste twice. Older hosts do not advertise screen clipboard support; update both Macs instead of relying on the clipboard polling interval.

The directed screen-control operations use the reliable control queue so clipboard parts precede subsequent keyboard events. Standard AppKit Edit-menu actions and keyboard events use this same directed path. They do not depend on the optional call-wide sync toggle. No clipboard text is persisted by Pairwise.

`ScreenClipboardTests` covers multipart/replay behavior, Unicode and JSON expansion, asynchronous and stale copies, consent revocation, private content, and failed input injection. `ScreenClipboardIntegrationTests` drives the actual canvas keyboard handler and two production `RTCService` clients over local LiveKit using independent pasteboards, production CGEvent construction, AppKit menu dispatch, and a native NSTextView destination. Only system-wide event posting is replaced to avoid typing into unrelated applications on the test runner. Run it with `sh scripts/test-call.sh`; the macOS CI gate includes it. This verifies transport and application logic, not physical screen capture, TCC approval, or native paste into a teammate's real application. Complete the physical Mac checks below before release.

### Two-Mac acceptance

With harmless synthetic text, verify both directions in TextEdit, a browser input, and a code editor. Repeat with multiline code, emoji/non-Latin text, a near-64-KiB clip, repeated copies of identical text, and a clipboard copied before the call. Confirm `⌘V` inserts the new text once, and `⌘C` returns the current selection. Try a first interaction without an existing control lease. Leave both call-wide sync toggles off and verify copy/paste works with no review prompt. Then pause control, revoke Accessibility, switch source, disconnect, and reconnect; no canceled operation should write or paste later. Verify focus changes and local text fields keep their normal shortcuts. Images/files and over-limit text must not paste stale text. Record hardware, macOS versions, application versions, and outcomes in the physical acceptance record.
